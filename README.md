
#  PCAP 어떻게 모았는지 수집 절차(Discussion)를 정리한 문서

## 1. 실험 구성(Topology / 구성도)

본 실험은 VMware 기반 가상 환경에서 **VM 2대(클라이언트/서버)**를 구성하고, vSomeIP(SOME/IP) UDP 통신을 발생시킨 뒤 Wireshark로 패킷을 캡처하여 PCAPNG 파일로 저장하였다.

### 구성도(텍스트)

```
[Local OS(Host PC)]
   └─ (VMware Virtual Network: 192.168.40.0/24, NIC: ens33)

      ┌───────────────────────────────┐        ┌───────────────────────────────┐
      │ Client VM (Ubuntu 20.04)      │        │ Server VM (Ubuntu 20.04)      │
      │  - NIC: ens33                 │        │  - NIC: ens33                 │
      │  - IP: 192.168.40.135         │ <----> │  - IP: 192.168.40.134         │
      │  - SOME/IP Client/Control     │        │  - SOME/IP Service Provider   │
      └───────────────────────────────┘        └───────────────────────────────┘
```

- Client VM: `192.168.40.131/24` (ens33)
    
- Server VM: `192.168.40.132/24` (ens33)
    
- 기본 게이트웨이(서버 측 라우팅 정보 기준): `192.168.40.2`

## 2. 사용 도구/버전

- OS: Ubuntu 20.04 (Client VM / Server VM)
    
- 가상화: VMware (VM 2대 구성)
    
- 통신 미들웨어: vSomeIP (로그에서 vSomeIP **3.1.37.1** 확인)
    
- 캡처 도구: Wireshark 3.2.3 (Git v3.2.3 packaged as 3.2.3-1)

    

---

## 3. 캡처 지점/인터페이스(어디서 잡았는가)

- 캡처 인터페이스: **ens33**
    
- 캡처 위치: 클라이언트 VM 및 서버 VM 모두에서 캡처 가능하나, 본 실험에서는 “통신이 실제로 왕복하는지”를 확인하기 위해 **클라이언트 ens33에서 UDP 31000 트래픽을 tcpdump로도 검증**하였다.
    
- 서버 측 포트 리스닝 확인:
    
    - `sudo ss -uapn | egrep '31000|vsomeip|someip'` 결과에서  
        `192.168.40.132:31000` UDP 리스닝(프로세스: PlaygroundService 계열) 확인

## 4. 캡처 시간/패킷 수(시작/종료 시각, 총량)

- 캡처는 Wireshark에서 Start/Stop 버튼을 사용해 수행하였다.
    
- 트래픽 발생은 클라이언트에서 **요청/응답 호출을 반복 실행하여** 확보하였다.
    
- 패킷 수는 “반복 호출 횟수”에 비례하여 증가하며, 실제 캡처 파일에서 Wireshark 하단 상태바 또는 Statistics에서 **총 패킷 수를 확인 가능**하다.
    
    - 3000개 가량
        
- 캡처 시작/종료 시각은 Wireshark 상단 표시 또는 파일 메타데이터 기준으로 기록한다.  
    (본 문서에는 절차를 우선 기술하고, 최종 제출 시 캡처 파일 기준의 정확한 시각/패킷 수를 기입한다.)
    

> **중요:** 교수님이 “블라인드”를 지적한 이유는 “패킷이 언제/왜 생겼는지”가 PCAP만으로는 불명확하기 때문이므로, 캡처 파일 제출 시 반드시  
> (1) 시작 시각, (2) 종료 시각, (3) 총 패킷 수를 함께 기재한다.
-> 이건 기록을 못했으므로, 다음 테스트시 제대로 기록할 것

## 5. 필터 및 디코딩(어떻게 골라서 봤는가)

### 5.1 캡처 필터(Capture Filter)

- 실험의 핵심 트래픽은 SOME/IP UDP 통신이며, 서버가 UDP **31000** 포트를 사용하므로 다음 캡처 필터를 사용하였다.
    
- 캡처 필터:
    
    - `udp port 31000`
        

### 5.2 디스플레이 필터(Display Filter)

- 캡처 후 화면에서 확인을 쉽게 하기 위해 다음 필터를 사용할 수 있다.
    
- 예시:
    
    - `udp.port == 31000`
        
    - `ip.addr == 192.168.40.131 || ip.addr == 192.168.40.132`
        

### 5.3 SOME/IP 디코딩 여부

- Wireshark에서 UDP 트래픽을 SOME/IP로 해석하기 위해 필요 시 **Decode As…** 기능을 사용하여  
    `UDP port 31000`을 SOME/IP로 디코딩하도록 설정할 수 있다.
    
- 최종 보고서에는 “Decode As 사용 여부”를 명시하여, 패킷 해석 과정의 재현성을 확보한다.

## 6. 트래픽 시나리오(무슨 동작으로 패킷이 발생했는가)

본 실험의 트래픽은 “서버 제공 서비스”에 대해 “클라이언트 제어 프로그램이 요청/응답을 수행”하면서 발생하였다. 실행 순서와 호출 동작은 다음과 같다.

### 6.1 실행 순서(재현 가능한 순서)

1. **Server VM**
    
    - SOME/IP 서버(서비스 제공자)를 먼저 실행하여 UDP 31000 리스닝 상태를 만든다.
        
    - 리스닝 확인:
        
        - `sudo ss -uapn | grep 31000`
            
2. **Client VM**
    
    - 제어 클라이언트(PlaygroundControlClient)를 실행하여 서버에 요청/응답을 발생시킨다.
        
    - 사용 스크립트:
        
        - `./run_control_net.sh`
            
3. **트래픽 확장(반복 호출)**
    
    - 패킷을 “많이” 확보하기 위해, ControlClient 실행을 **1000회 반복**했다.
        
    - 사용한 반복 명령:
        
        - `./run_control_net_loop.sh 1000`
            

### 6.2 발생시킨 기능 호출(요청/응답의 원인)

클라이언트 실행 로그에서 실제로 다음과 같은 제어/조회 동작이 수행되며, 이 과정에서 SOME/IP 요청/응답 트래픽이 생성된다.

- 예시(로그 기반):
    
    - `getDoorsOpeningStatusAttribute` : 도어 상태 조회(전/후)
        
    - `initTirePressureCalibration` : 타이어 압력 캘리브레이션 초기화 호출
        
    - `changeDoorsState(OPEN_DOOR, CLOSE_DOOR, OPEN_DOOR, CLOSE_DOOR)` : 도어 상태 변경 호출
        

즉, 시나리오를 한 문장으로 요약하면 다음과 같다.

> “서버를 미리 실행하여 서비스 제공 상태를 유지한 뒤, 클라이언트에서 ControlClient를 실행하여 **조회/제어 요청을 반복(1000회) 발생**시키고, 그 과정에서 생성되는 SOME/IP UDP 트래픽(31000)을 Wireshark로 캡처하였다.”

## 7. 통신 정상 여부 검증(캡처 전에 무엇을 확인했는가)

- 서버 포트 리스닝 확인(UDP 31000)
    
- 클라이언트에서 실제 왕복 트래픽 확인을 위해 tcpdump 사용:
    
    - `sudo tcpdump -ni ens33 -vv udp port 31000`
        
- tcpdump 출력에서 Client→Server, Server→Client의 UDP 패킷 왕복이 관측되어 통신이 정상임을 확인하였다.
    
- 또한 방화벽(UFW)이 통신에 영향을 줄 수 있어, 필요 시 `sudo ufw status` 확인 후 조치(포트 허용 또는 비활성화)하였다.

## 8. 캡처 파일 저장 형식

- 저장 형식: **pcapng** (Wireshark 기본, 메타데이터 포함)
    
- 파일명에는 “누가/어디서/무슨 포트/언제”를 포함하여 블라인드를 최소화한다.
    
    - 예: `client_ens33_udp31000_YYYYMMDD_HHMM.pcapng`
        
    - 예: `server_ens33_udp31000_YYYYMMDD_HHMM.pcapng`
